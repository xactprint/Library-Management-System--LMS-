# 1. Requirement Analysis

## 1.1 Project Overview

The Library Management System (LMS) is a software application designed to simplify and automate the daily operations of a library.

The system allows librarians to manage books, register members, process borrowing and returning transactions, and monitor book availability.

It also provides an interface for members to search for books and consult their borrowing information.

The main objective is to improve library management, reduce manual operations, ensure accurate record-keeping, and provide an efficient way to manage library resources.

## 1.2 System Objectives

The main objectives of the Library Management System are:

- Manage the library's book collection.
- Register and manage library members.
- Allow members to search for available books.
- Process book borrowing and returning operations.
- Track borrowing history and due dates.
- Identify overdue books.
- Provide administrative functions and reports.

## 1.3 System Scope

The system will include three main categories of users:

- **Librarian:** Manages books and borrowing/returning transactions.
- **Member:** Searches for books and consults personal borrowing information.
- **Administrator:** Manages system users, librarian accounts, and administrative settings.

The project focuses on a simplified library management system. Advanced features such as online payments, e-books, and external library integrations are outside the initial scope.

## 1.4 Functional Requirements

The system must provide the following functionalities:

| ID   | Functional Requirement                         |
| ---- | ---------------------------------------------- |
| FR01 | Add, update, and delete books.                 |
| FR02 | Search for books by title, author, or ISBN.    |
| FR03 | Register and manage library members.           |
| FR04 | Check book availability.                       |
| FR05 | Issue books to registered members.             |
| FR06 | Record returned books.                         |
| FR07 | Track borrowing due dates.                     |
| FR08 | Identify overdue books.                        |
| FR09 | View borrowing history.                        |
| FR10 | Manage librarian accounts and system settings. |
| FR11 | Generate basic library reports.                |

## 1.5 Non-Functional Requirements

The system should also satisfy the following quality requirements:

- **Usability:** The interface should be simple and user-friendly.
- **Security:** Only authorized users can access restricted functions.
- **Performance:** Searches and common operations should be processed efficiently.
- **Reliability:** Borrowing and returning records must remain accurate.
- **Maintainability:** The system should be modular and easy to update.
- **Scalability:** The architecture should support future improvements.
